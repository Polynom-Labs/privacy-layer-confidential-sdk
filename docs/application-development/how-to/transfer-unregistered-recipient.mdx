## Transact environment hooks

Unregistered recipients need `resolveTransferRecipientAtExecute` on `transactEnvironment`. The default chain resolver (`resolveTransferRecipientFromChain`) looks up the registry, then **derives an escrow key** from a random nonce and the recipient's Stellar G-address. That pins exactly one recipient to the note. Public escrow recipient limbs stay zero on send, so the transaction matches an ordinary private transfer.

The hook is registered during client bootstrap (see [Setup](/application-development/setup)). Custom resolvers should return `escrowSend` with the derived nonce and G-address limbs rather than a temporary private address.

```ts
const transactEnvironment = {
  // ...network, kyt, signTransaction from setup
  resolveTransferRecipientAtExecute: async ({ recipientStellarAddress, walletPublicKey }) => {
    return client.resolveTransferRecipient({
      recipientStellarAddress,
      walletPublicKey,
    });
  },
};
```

Escrow sends require Protocol Relay and a zero public deposit. A positive public deposit is refused (not downgraded to Direct Submission). If relay is unconfigured, submission fails with `escrow_relay_unconfigured` and wallet submission is not offered.

## Example

Call `transfer` with a public Stellar `to` address and the same private disclosure as a registered transfer.

### Seed state

```tsx
const POOL = 'CBVQTSTSIJ4UZMN5FQBFHPUIYSW3ATGSP57BZDJNKTOBNQODQTRGE4K5';
const SENDER = 'GDSENDER7EXAMPLEPUBLICKEYAAAAAAAAAAAAAAAAAAAA';
const SENDER_PRIVATE = 'stpl1sender7exampleprivateaddress0000000000';
const RECIPIENT = 'GCRECIPIENT7EXAMPLEPUBLICKEYAAAAAAAAAAAAAAA';

await client.upsertAssets([
  {
    id: 1,
    assetId: 'usdc',
    name: 'USDC',
    logoUrl: null,
    issuerAddress: null,

await client.saveWalletPrivateAddressScalar({

```

### Run operation

```tsx
const operation = await client.transfer({
  from: 'stpl1sender7exampleprivateaddress0000000000',
  to: 'GCRECIPIENT7EXAMPLEPUBLICKEYAAAAAAAAAAAAAAA',
  asset: 'usdc',
  amount: 25_0000000n,
  disclosure: {
    senderAddress: 'private',
    recipientAddress: 'private',
    assetAddress: 'private',
    amount: 'private',
  },
});

if (operation.status === 'rejected') {
  throw new Error(operation.errors[0]?.message);
}

await operation.execute({});
```

The SDK derives the escrow note owner at execute. It does not put the recipient G-address in pool calldata or the relay package on send.

## Discover notes sent before registration

A recipient who registers later can still find notes that were sent to their public wallet. They prove control of that wallet by signing a challenge in the same labeled-line shape used to derive a private-note spend key. `buildBlindedRecipientTagChallengeMessage` builds that exact UTF-8 string so it matches issuance.

Sign the message with a current account signer, then present the signature to your tag-issuance integration. Issued **blinded recipient tags** (one per tag epoch) are how the recipient looks up notes without revealing their address to the index. Claiming those notes is a separate flow.

```ts
import { buildBlindedRecipientTagChallengeMessage } from '@arcanetech/privacy-sdk-stellar/transact';

const message = buildBlindedRecipientTagChallengeMessage({
  stellarAddress: walletPublicKey,
  networkPassphrase: transactEnvironment.network.networkPassphrase,
  issuedAt,
  expiresAt,
  nonce,
});
const signature = await wallet.authorizeMessage(message);
```

Do not reconstruct the message by hand. Issuance verifies the signed string byte-for-byte.
