Make your first private deposit in minutes using the frontend wallet demo or the backend Node demo.

Each path clones a reference app with live stand values — not tutorial fixtures. After you finish either demo, replace stand values with your own pool and Compliance application. See [Getting access](/integration/getting-access) and [Data sources](/integration/data-sources).

## Choose your implementation path

| Path         | Best for                                         | Complexity |
| ------------ | ------------------------------------------------ | ---------- |
| **Frontend** | Browser wallet UI (Freighter), Redux state       | Low        |
| **Backend**  | Node signing service, in-memory state + Postgres | Medium     |

Both demos share the same testnet pool, registry, and `zkConfigNonce` **7**. They do **not** share the same Compliance `applicationId`, audit key, KYT URL, or Relayer origin — copy env from the demo you run.

Deposit keeps the sender **public** and uses Direct Submission (`operation.execute()`). Private-sender transfers, withdraws, and escrow sends use [`@arcanetech/privacy-sdk-relay`](https://www.npmjs.com/package/@arcanetech/privacy-sdk-relay).

    ### Prerequisites

    - Node.js 20 or later
    - [Freighter](https://www.freighter.app/) on Stellar **testnet**
    - A normal Chrome or Firefox window (the Cursor embedded browser cannot approve wallet popups)

    ### Step 1 — Clone and install

    ```bash
    git clone https://github.com/Polynom-Labs/pl-frontend-sdk-demo.git
    cd pl-frontend-sdk-demo
    cp .env.example .env
    npm install
    npm run dev
    ```

    Defaults target the Stellar Pay testnet stand. `VITE_AUDIT_PUBLIC_KEY_HEX` must be the Compliance application key for that stand — the SDK bundled demo key lets bootstrap succeed, but live `execute()` may fail.

    ### Step 2 — Set environment

    | Variable | Role |
    | --- | --- |
    | `VITE_POOL_CONTRACT` | Privacy pool (`C…`) |
    | `VITE_REGISTRY_CONTRACT` | Private-address registry (`C…`) |
    | `VITE_APPLICATION_ID` | `association.audit_id` (decimal Fr, not a UUID) |
    | `VITE_ZK_CONFIG_NONCE` | Must match on-chain pool `ZkConfig` (this stand: `7`) |
    | `VITE_KYT_API_BASE_URL` / `VITE_KYT_REGISTRY_CONTRACT` | KYT inspect |
    | `VITE_AUDIT_PUBLIC_KEY_HEX` | Application audit public key |
    | `VITE_RELAY_ORIGIN` | Protocol Relay base URL |
    | `VITE_RPC_URL` / `VITE_NETWORK_PASSPHRASE` / `VITE_HORIZON_URL` | Testnet defaults are public |

    Packages: `@arcanetech/privacy-sdk-stellar`, `@arcanetech/privacy-sdk-state-redux`, `@arcanetech/privacy-sdk-relay`.

    ### Step 3 — Run the UI flow

    1. Connect Freighter
    2. **Create private address** (or **Restore** if the wallet is already on-chain)
    3. **Deposit** public XLM into Private XLM
    4. **Transfer** to a `G…` or `stpl1…` address
    5. **Withdraw** back to the connected account

    Deposit uses Direct Submission. Transfer, withdraw, and escrow send go through Protocol Relay. An unregistered `G…` is an escrow send — the recipient accepts it after they register (**Incoming transfers** → **Accept**). Accept is Direct, not Relay.

    ### Step 4 — How the client boots

    ```ts
    import {
      createDefaultTransactEngine,
      createStellarPolicyAdapterFromEnvironment,
      createStellarPrivacyClientFromResolvedConfig,
      resolveStellarPrivacyClientConfig,
    } from '@arcanetech/privacy-sdk-stellar';

    const transactEnvironment = {
      network: {
        id: 'stellar-testnet',
        rpcUrl: import.meta.env.VITE_RPC_URL,
        networkPassphrase: import.meta.env.VITE_NETWORK_PASSPHRASE,
        poolContract: import.meta.env.VITE_POOL_CONTRACT,
        registryContract: import.meta.env.VITE_REGISTRY_CONTRACT,
        applicationId: import.meta.env.VITE_APPLICATION_ID,
      },
      zkConfigNonce: BigInt(import.meta.env.VITE_ZK_CONFIG_NONCE),
      kyt: {
        apiBaseUrl: import.meta.env.VITE_KYT_API_BASE_URL,
        kytPassageRegistryContract: import.meta.env.VITE_KYT_REGISTRY_CONTRACT,
      },
      signTransaction: signXdr, // Freighter via your wallet adapter
    };

    const assets = await loadPrivacySdkWasm();
    const resolved = await resolveStellarPrivacyClientConfig({
      network: transactEnvironment.network,
      wallet,
      state: reduxStateAdapter,
      assets,
      auditPublicKeyHex: import.meta.env.VITE_AUDIT_PUBLIC_KEY_HEX,
      transactEnvironment,
      policy: createStellarPolicyAdapterFromEnvironment(transactEnvironment),
    });
    const client = await createStellarPrivacyClientFromResolvedConfig(resolved, {
      transact: createDefaultTransactEngine(resolved.config.transactEnvironment),
    });
    ```

    Full React shell: [Setup](/application-development/setup).

    ### Step 5 — Deposit, then choose Direct or Relay

    ```ts
    const operation = await client.deposit({
      from: owner,
      to: privateAddress,
      asset: 'XLM',
      amount,
      disclosure: {
        senderAddress: 'public',
        recipientAddress: 'private',
        assetAddress: 'public',
        amount: 'public',
      },
    });

    if (operation.status === 'rejected') {
      throw new Error(operation.errors[0]?.message ?? 'Prepare failed');
    }

    await operation.execute({
      onEvent(event) {
        if (event.status === 'begin') {
          console.log(`[${event.stage}] started`);
        }
      },
    });
    ```

    For withdraw, private-sender transfer, or escrow send, call `requiredSubmissionMethod` after prepare. When the method is `relay`, do **not** call `execute()` — submit through `@arcanetech/privacy-sdk-relay` with `relayConfig.origin` set. See the demo `relay.ts` and [Withdraw](/application-development/how-to/withdraw).

    ### Notes

    - SDK domain state is a Redux snapshot persisted as `privacy-sdk-state:v1:<G-address>`. Treat that store like a secret.
    - Incoming notes for another registered `stpl1` land in this browser’s `localStorage`.

    ### Prerequisites

    - Docker (recommended) or Node 20 + Postgres 16
    - A BIP-39 `STELLAR_MNEMONIC` (secrets stay in env, not in the database)
    - A Relayer origin for private-sender and escrow paths (`RELAYER_ORIGIN`)

    ### Step 1 — Clone and install

    ```bash
    git clone https://github.com/Polynom-Labs/pl-backend-sdk-demo.git
    cd pl-backend-sdk-demo
    cp .env.example .env
    ```

    Start Postgres (or `docker compose up postgres`), point `DATABASE_URL` at it, then:

    ```bash
    npm install
    npm run start:dev
    ```

    Point `RELAYER_ORIGIN` at your Relayer (local `relayer-service` or the hosted URL in `.env.example`). Without origin, private-sender and escrow sends fail with `escrow_relay_unconfigured`.

    ### Step 2 — Set environment

    | Variable | Role |
    | --- | --- |
    | `POOL_CONTRACT` / `REGISTRY_CONTRACT` | Privacy pool and registry (`C…`) |
    | `APPLICATION_ID` | `association.audit_id` (decimal Fr, not a UUID) |
    | `ZK_CONFIG_NONCE` | Must match on-chain pool `ZkConfig` (this stand: `7`) |
    | `KYT_API_BASE_URL` / `KYT_PASSAGE_REGISTRY_CONTRACT` | KYT inspect |
    | `STELLAR_AUDIT_PUBLIC_KEY` | Application audit public key |
    | `RELAYER_ORIGIN` | Protocol Relay base URL |
    | `STELLAR_MNEMONIC` | HD seed for server-side signing |
    | `DATABASE_URL` | Postgres for SDK state snapshots |
    | `SOROBAN_RPC_URL` / `HORIZON_URL` / passphrase | Testnet defaults are public |

    Packages: `@arcanetech/privacy-sdk-stellar` (Node entry), `@arcanetech/privacy-sdk-state-memory`, `@arcanetech/privacy-sdk-relay`.

    <Warning>
      This demo’s `APPLICATION_ID`, audit key, KYT URL, and Relayer origin differ from the frontend demo even when the pool and registry match. Copy env from **this** repo.
    </Warning>

    ### Step 3 — Call the API

    Default listen port is `3000`.

    1. `POST /api/setup` — derive HD keys, Friendbot, register private addresses
    2. `POST /api/deposit` `{ "amountXlm": 10 }` — public-sender deposit (Direct)
    3. `POST /api/simulator/start` `{ "amountXlm": 1, "transactionsPerMinute": 2 }` — private transfers through Relay
    4. `POST /api/simulator/stop`
    5. `POST /api/withdraw` `{ "accountIndex": 0, "amountXlm": 1 }`
    6. `GET /api/state` — inspect balances and SDK snapshot

    ### Step 4 — How the Node client boots

    ```ts
    import { createInMemoryStateAdapter } from '@arcanetech/privacy-sdk-state-memory';
    import { createStellarPrivacyClientFromNodeConfig } from '@arcanetech/privacy-sdk-stellar/node';

    const state = createInMemoryStateAdapter();

    const client = await createStellarPrivacyClientFromNodeConfig({
      network: {
        id: 'stellar-testnet',
        rpcUrl: process.env.SOROBAN_RPC_URL!,
        networkPassphrase: process.env.STELLAR_NETWORK_PASSPHRASE!,
        poolContract: process.env.POOL_CONTRACT!,
        registryContract: process.env.REGISTRY_CONTRACT!,
        applicationId: process.env.APPLICATION_ID!,
      },
      zkConfigNonce: BigInt(process.env.ZK_CONFIG_NONCE ?? '7'),
      wallet, // server keypair adapter
      state,
      sdkWasmPath, // filesystem path to bundled WASM
      auditPublicKeyHex: process.env.STELLAR_AUDIT_PUBLIC_KEY!,
      transactEnvironment: {
        /* network, kyt, signTransaction, zkConfigNonce */
      },
    });
    ```

    See [State integration](/integration/state-integration) and [Integration paths — Node](/integration/integration-paths#node-path-stellar-preset).

    ### Step 5 — Direct deposit vs Relay

    Deposit keeps the sender public and calls `operation.execute()` (Direct Submission).

    Private-sender transfers and withdraws call `requiredSubmissionMethod` after prepare. When the method is `relay`, submit through `@arcanetech/privacy-sdk-relay` with `RELAYER_ORIGIN` — do **not** call wallet `execute()` for that path.

    Full patterns: [Withdraw](/application-development/how-to/withdraw), [Transfer to unregistered recipient](/application-development/how-to/transfer-unregistered-recipient).

    ### Notes

    - Incoming notes for other HD accounts are remapped onto the recipient G-address after each transfer.
    - Tutorial fixture contract IDs from how-to pages will not confirm on testnet.
