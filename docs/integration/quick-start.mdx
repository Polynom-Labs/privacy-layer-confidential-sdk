This tutorial walks through a **minimal Stellar preset** integration using an **in-memory state adapter**.

For React wiring, see [Setup](/application-development/setup).

## What you will build

A short script that:

1. Creates a Stellar privacy client with in-memory state.
2. Seeds the minimum fixture data prepare expects.
3. Calls `deposit`, checks the prepare result, and runs `execute` with progress logging.
4. Optionally routes later operations through Protocol Relay when Direct Submission is not allowed.

## Prerequisites

- Node.js 20.10 or later. `@stellar/stellar-sdk` 16 (pulled by the Stellar preset) declares Node 22+; install on 20.10 may print `EBADENGINE`.
- Packages: [`@arcanetech/privacy-sdk-stellar`](https://www.npmjs.com/package/@arcanetech/privacy-sdk-stellar), [`@arcanetech/privacy-sdk-state-memory`](https://www.npmjs.com/package/@arcanetech/privacy-sdk-state-memory)
- Optional: [`@arcanetech/privacy-sdk-relay`](https://www.npmjs.com/package/@arcanetech/privacy-sdk-relay) for private-sender and escrow-send paths (Step 6)
- Live IDs and keys: [Getting access](/integration/getting-access). The contract IDs below are fixtures.

```bash
npm install @arcanetech/privacy-sdk-stellar @arcanetech/privacy-sdk-state-memory
```

For Redux and React, see [Install](/application-development/install). For Protocol Relay, also install `@arcanetech/privacy-sdk-relay`.

## Step 1 — Create an in-memory state adapter

Prepare reads local domain data — private records, pool snapshot, registry cache, wallet keys. If notes, pool root, or wallet secrets are missing or stale, prepare returns `rejected` with `insufficient_state` instead of opening the wallet.

An in-memory adapter stores this data in process memory. It does not survive reloads.

<Tip>
  Pass the adapter to `createStellarPrivacyClient` as `state`. The SDK reads and updates domain data through the adapter — you do not implement storage APIs yourself.
</Tip>

```ts
import { createInMemoryStateAdapter } from '@arcanetech/privacy-sdk-state-memory';

const state = createInMemoryStateAdapter();
```

## Step 2 — Add a wallet adapter

The Stellar preset signs through a wallet adapter. The `G…` value below is **not** a valid Stellar public key — it is a stub. Replace it with your wallet SDK before you send live transactions.

```ts
import type { StellarWalletAdapter } from '@arcanetech/privacy-sdk-stellar';

const wallet: StellarWalletAdapter = {
  getAddress: async () => 'GDSENDER7EXAMPLEPUBLICKEYAAAAAAAAAAAAAAAAAAAA',
  authorizeMessage: async (message) =>
    new TextEncoder().encode(typeof message === 'string' ? message : ''),
  signTransactionPayload: async (payload) => ({ ...payload, signed: true }),
};
```

<Tip>
  `getAddress` identifies the connected account. `authorizeMessage` proves control of a private payment address. `signTransactionPayload` signs the Soroban transaction XDR before submission.
</Tip>

## Step 3 — Create the client

Load bundled runtime assets, configure Soroban network contracts, and create the client once.

<Warning>
  Contract IDs, KYT, `applicationId`, and `auditPublicKeyHex` in this block are **tutorial fixtures**. `auditPublicKeyHex` is the SDK bundled demo key (valid BabyJubJub format) — not a production application key. A live `execute()` needs your stand’s pool, registry, KYT, application ID, and audit key. `applicationId` may be a UUID or a numeric string depending on the stand. See [Data sources](/integration/data-sources).
</Warning>

```ts
import {
  createStellarPolicyAdapterFromEnvironment,
  createStellarPrivacyClient,
  isStellarPrivacyClient,
  loadDefaultStellarBrowserAssets,
} from '@arcanetech/privacy-sdk-stellar';
import type { StellarTransactEnvironment } from '@arcanetech/privacy-sdk-stellar/transact';

const transactEnvironment: StellarTransactEnvironment = {
  network: {
    id: 'stellar-testnet',
    rpcUrl: 'https://soroban-testnet.stellar.org',
    networkPassphrase: 'Test SDF Network ; September 2015',
    poolContract: 'CBVQTSTSIJ4UZMN5FQBFHPUIYSW3ATGSP57BZDJNKTOBNQODQTRGE4K5',
    registryContract: 'CCO5QRTS5HFVPR356FFC4NI62IMBQNDGMOAXR4K5UVTV3YMRWDZGKXGC',
    applicationId: '00000000-0000-0000-0000-000000000001',
  },
  kyt: {
    apiBaseUrl: 'https://example.invalid',
    kytPassageRegistryContract: 'CKYTEXAMPLECONTRACTIDAAAAAAAAAAAAAAAAAAAAAA',
  },
  signTransaction: async ({ xdr }) => ({ signedTxXdr: xdr }),
};

const assets = await loadDefaultStellarBrowserAssets();

const created = await createStellarPrivacyClient({
  network: transactEnvironment.network,
  wallet,
  state,
  assets,
  // SDK bundled demo audit key. Replace with your application key in production.
  auditPublicKeyHex:
    '042fc449e2dd0c5349d06092adc126e213858984584e429842d87bcc705837c76529b060ee13f1da3bde25e0e11c23a145656ede61710ed78593d69b8bdbc1a581',
  transactEnvironment,
  policy: createStellarPolicyAdapterFromEnvironment(transactEnvironment),
});

if (!isStellarPrivacyClient(created)) {
  throw new Error('Client creation failed');
}

const client = created;
```

<Tip>
  `loadDefaultStellarBrowserAssets()` is the **browser** loader (Vite / SPA). It uses `fetch` on a WASM URL and fails in Node. For a Node service use [`@arcanetech/privacy-sdk-stellar/node`](/integration/integration-paths#node-path-stellar-preset) with a filesystem `sdkWasmPath`. Proving artifacts download from the CDN for the SDK version unless `transactEnvironment.zkArtifactBaseUrl` overrides that URL (used by local stands). `transactEnvironment` also ties together network contracts, optional KYT, and your app's transaction signing hook.
</Tip>

## Step 4 — Seed fixture state

The block below is **tutorial fixture data**. In production, assets and wallet secrets come from your backend and wallet flows. See [Data sources](/integration/data-sources).

```ts
const POOL = transactEnvironment.network.poolContract;
const OWNER = await wallet.getAddress();
const PRIVATE_ADDRESS = 'stpl1sender7exampleprivateaddress0000000000';

await client.upsertAssets([
  {
    id: 1,
    assetId: 'usdc',
    name: 'USDC',
    logoUrl: null,
    issuerAddress: null,
    clientContract: 'CTOKENCONTRACTEXAMPLEAAAAAAAAAAAAAAAAAAAAAA',
    poolContracts: [POOL],
    poolContract: POOL,
    mintable: false,
    mintAmount: null,
  },
]);
await client.saveWalletPrivateAddressRecord({
  owner: OWNER,
  nonce: '1',
  privateAddress: PRIVATE_ADDRESS,
  createdAt: Date.now(),
});
await client.saveWalletPrivateAddressScalar({
  owner: OWNER,
  nonce: '1',
  scalarHex: '0xabc123scalarhexexample000000000000000000000000000000000000',
});
await client.setWalletDefaultPrivateAddressNonce({ owner: OWNER, nonce: '1' });
await client.setPoolMerkleState({
  poolContract: POOL,
  commitments: ['0xmerklecommitmenthexexample00000000000000000000000000000000'],
  commitmentCount: 1,
  merkleRootHex: '0xmerkleroothexexample000000000000000000000000000000000000',
  updatedAt: Date.now(),
});
```

<Tip>
  Prepare checks this cache before asking the wallet to sign. Missing asset catalog rows or wallet scalars are common reasons for early `rejected` results.
</Tip>

## Step 5 — Prepare and execute

`execute()` submits to Soroban. With the fixture wallet and contracts above it will not confirm on testnet. Swap in a real wallet and stand before sending.

```ts
const operation = await client.deposit({
  from: OWNER,
  to: PRIVATE_ADDRESS,
  asset: 'usdc',
  amount: 50_0000000n,
  disclosure: {
    senderAddress: 'public',
    recipientAddress: 'private',
    assetAddress: 'public',
    amount: 'public',
  },
});

if (operation.status === 'rejected') {
  throw new Error(operation.errors[0]?.message ?? 'Prepare failed');
}

await operation.execute({
  onEvent(event) {
    if (event.status === 'begin') {
      console.log(`[${event.stage}] started`);
    }
  },
});
```

<Tip>
  Always branch on `operation.status` before calling `execute()`. Use `onEvent` to drive progress UI — stages are listed in [Operation lifecycle](/concepts/operation-lifecycle).
</Tip>

Deposit keeps the sender **public** and uses a positive public deposit, so Direct Submission (`execute()`) is the correct path. Skip Step 6 unless you are submitting a private-sender or escrow-send operation.

## Step 6 — Protocol Relay (optional)

`operation.execute()` is **Direct Submission**: the connected wallet signs and the transact engine submits to Soroban. It never calls `@arcanetech/privacy-sdk-relay`.

After prepare, choose the path with `requiredSubmissionMethod` from `@arcanetech/privacy-sdk-stellar/transact`:

- **`direct`** — positive public deposit (typical deposit). Call `operation.execute()`.
- **`relay`** — zero public deposit (private sender) or an **escrow send** to an unregistered recipient. Do **not** call `execute()`. Build a relay package and submit through the relay runtime.
- Escrow **sweeps** stay Direct so the claimant wallet signs the envelope.

Relaying is off until `relayConfig.origin` is set. An unset origin Direct-submits a typical deposit and never contacts a relayer. An **escrow send** without origin fails with `escrow_relay_unconfigured` — it is not downgraded to Direct.

`store`, `submitDirect`, `finalizeLocalState`, `drainDeliveries`, `persistUserTransaction`, `relayOriginFromEnv`, and `relayOperation` below are **your** implementations — the SDK does not export them.

```ts
import { requiredSubmissionMethod } from '@arcanetech/privacy-sdk-stellar/transact';
import {
  createRelayApi,
  resolveRelayOrigin,
  submitAndAwaitPrivateOperation,
  throwIfRelayUnsuccessful,
  type ProtocolRelayPorts,
} from '@arcanetech/privacy-sdk-relay';

if (operation.status !== 'prepared') {
  throw new Error(operation.errors[0]?.message ?? 'Prepare failed');
}

const method = requiredSubmissionMethod(operation.prepared);

if (method === 'direct') {
  await operation.execute({
    onEvent(event) {
      if (event.status === 'begin') {
        console.log(`[${event.stage}] started`);
      }
    },
  });
} else {
  // Implement these in your app — they are not SDK exports.
  const origin = resolveRelayOrigin(relayOriginFromEnv);
  const ports: ProtocolRelayPorts = {
    store,
    submitDirect,
    finalizeLocalState,
    drainDeliveries,
    persistUserTransaction,
    ...(origin
      ? { relayConfig: { origin }, relayApi: createRelayApi({ origin }) }
      : {}),
  };
  const result = await submitAndAwaitPrivateOperation({
    ports,
    operation: relayOperation,
  });
  throwIfRelayUnsuccessful(result);
}
```

Build `relayOperation` (`NewPrivateOperation`) in your app: set `submissionPath: 'relay'`, serialize the package with `prepareRelayTransactPackageFromPrepared` + `serializeRelayPackage`, and implement the five ports (`store`, `submitDirect`, `finalizeLocalState`, `drainDeliveries`, `persistUserTransaction`). The relay runtime does not inspect the opaque package payload. See [`@arcanetech/privacy-sdk-relay`](/overview/packages) and the [withdraw](/application-development/how-to/withdraw) / [unregistered transfer](/application-development/how-to/transfer-unregistered-recipient) how-tos.
